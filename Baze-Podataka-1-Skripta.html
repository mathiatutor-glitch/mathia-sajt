Baze podataka 1

Relacioni model, SQL osnove, spajanja, agregacije i normalizacija — korak po korak.
✦
← Nazad na predmet
O čemu je predmet. Osnove baza podataka: relacioni model i ključevi, relaciona algebra, SQL (SELECT, WHERE, JOIN, GROUP BY, HAVING, agregatne funkcije), funkcionalne zavisnosti i normalne forme (1NF–3NF) i ER modelovanje. Fokus je na razumevanju i pisanju ispravnih upita.

1.Relacioni model i ključevi

Baza je skup tabela. Svaka tabela ima kolone (atribute) i redove. Primarni ključ jedinstveno određuje red i ne sme biti NULL. Strani ključ povezuje tabele i mora upućivati na postojeći primarni ključ (referencijalni integritet).

CREATE TABLE Student (
  id    INTEGER PRIMARY KEY,
  ime   VARCHAR(50) NOT NULL,
  smer  VARCHAR(10)
);
Zapamti
CREATE TABLE definiše kolone, tipove i ograničenja (PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK).

2.Relaciona algebra

Operacije nad relacijama: σ (selekcija — bira redove po uslovu), π (projekcija — bira kolone), ⋈ (spajanje po zajedničkom atributu) i skupovne operacije (∪, ∩, −, ×). Svaki SQL upit se može izraziti relacionom algebrom.

3.SQL osnove: SELECT i WHERE

Upit bira kolone iz tabele i filtrira redove: SELECT kolone FROM tabela WHERE uslov. Korisni operatori: =, <, >, AND, OR, NOT, LIKE, BETWEEN, IN, IS NULL. DISTINCT uklanja duplikate, ORDER BY sortira.

SELECT DISTINCT ime
FROM   Student
WHERE  smer = 'RN' AND ime LIKE 'M%'
ORDER  BY ime;

4.Spajanje tabela (JOIN)

INNER JOIN vraća samo uparene redove; LEFT JOIN zadržava sve redove leve tabele (bez para → NULL); RIGHT JOIN obrnuto. Uslov spajanja se piše u ON (obično strani ključ = primarni ključ).

SELECT s.ime, o.ocena
FROM   Student s
LEFT JOIN Ocena o ON o.student_id = s.id;

5.Agregacije i grupisanje

COUNT, SUM, AVG, MIN, MAX sažimaju grupu redova. GROUP BY deli redove u grupe (npr. po smeru), a HAVING filtrira grupe po agregatnoj vrednosti. WHERE filtrira pre grupisanja, HAVING posle.

SELECT smer, COUNT(*) AS broj, AVG(ocena) AS prosek
FROM   Student s JOIN Ocena o ON o.student_id = s.id
GROUP  BY smer
HAVING COUNT(*) >= 5;

6.Zavisnosti i normalne forme

Funkcionalna zavisnost X → Y: X određuje Y. 1NF: sve vrednosti atomske (bez lista u ćeliji). 2NF: 1NF + nema parcijalne zavisnosti neključnog atributa od dela složenog ključa. 3NF: 2NF + nema tranzitivne zavisnosti (neključni atribut ne zavisi od drugog neključnog).

Zapamti
Normalizuj postupno: 1NF → 2NF → 3NF, izbacujući problematičnu zavisnost u novu tabelu i ostavljajući strani ključ.

7.ER modelovanje

ER dijagram sadrži entitete (npr. Student), atribute (ime, id) i veze sa kardinalnostima. Prevođenje: svaki entitet postaje tabela; veza 1:N daje strani ključ na strani „N“; veza M:N zahteva zasebnu spojnu tabelu sa oba strana ključa.
