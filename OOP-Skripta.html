Objektno orijentisano programiranje

Klase, objekti, četiri stuba, SOLID i UML — korak po korak.
✦
← Nazad na predmet
O čemu je predmet. OOP je paradigma u kojoj program gradimo od objekata — instanci klasa koje spajaju podatke i ponašanje. Obrađujemo četiri stuba (enkapsulacija, nasleđivanje, polimorfizam, apstrakcija), konstruktore, preklapanje i nadjačavanje, SOLID principe, UML dijagrame i složenost algoritama.

1.Klase i objekti

Klasa je nacrt (šablon), a objekat je konkretna instanca te klase. Klasa opisuje polja (stanje) i metode (ponašanje). Objekat se stvara operatorom new.

class Racun { private double stanje; // enkapsulacija: skriveno polje public Racun(double pocetno) { // konstruktor this.stanje = pocetno; } public void uplati(double x) { // metoda if (x > 0) this.stanje += x; } public double getStanje() { // geter return this.stanje; } }
Zapamti
Isti nacrt (klasa) daje mnogo objekata; svaki objekat ima svoje vrednosti polja, ali deli iste metode.

2.Četiri stuba OOP

Enkapsulacija — skrivanje podataka iza javnog interfejsa. Nasleđivanje — izvedena klasa preuzima članove osnovne. Polimorfizam — isti poziv, različito ponašanje zavisno od tipa. Apstrakcija — prikaz suštine, skrivanje detalja.

Zapamti
Enkapsulaciju postiži privatnim poljima i javnim metodama (geteri/seteri). To štiti nepromenljive uslove (invariante) objekta.

3.Konstruktori i destruktori

Konstruktor je posebna metoda koja inicijalizuje objekat pri kreiranju (isto ime kao klasa, bez povratnog tipa). Destruktor oslobađa resurse pri uništenju objekta; u jezicima sa sakupljačem smeća (Java, C#) tu ulogu ima finalizacija ili try-with-resources.

Zapamti
Ako ne napišeš konstruktor, jezik obično daje podrazumevani (bez argumenata). Čim definišeš svoj, podrazumevani nestaje.

4.Preklapanje i nadjačavanje

Preklapanje (overloading) — više metoda istog imena, ali različitih parametara, u istoj klasi (odlučuje se u vreme prevođenja). Nadjačavanje (overriding) — izvedena klasa daje novu implementaciju nasleđene metode istog potpisa (odlučuje se u vreme izvršavanja — dinamički polimorfizam).

class Matematika { int saberi(int a, int b) { return a + b; } double saberi(double a, double b){ return a + b; } // preklapanje int saberi(int a, int b, int c) { return a + b + c; } }class Zivotinja { public String glas() { return "..."; } } class Pas extends Zivotinja { @Override public String glas() { return "Av"; } // nadjacavanje (override) } Zivotinja z = new Pas(); z.glas(); // "Av" -> polimorfizam
Zapamti
Preklapanje = isti naziv, drugi parametri. Nadjačavanje = isti potpis, druga (izvedena) klasa. Ne mešaj ih!

5.SOLID principi

Pet principa dobrog dizajna: S — jedna odgovornost (SRP), O — otvoreno za proširenje, zatvoreno za izmenu (OCP), L — Liskovljeva zamenljivost (LSP), I — razdvajanje interfejsa (ISP), D — inverzija zavisnosti (DIP).

Zapamti
Znak kršenja SRP: klasa se menja iz više nepovezanih razloga. Podeli je na manje klase sa jasnom ulogom.

6.UML i veze klasa

UML dijagram klasa prikazuje klase i njihove veze. Asocijacija — klase koriste jedna drugu. Agregacija — celina–deo, ali deo živi nezavisno (prazan romb ◇). Kompozicija — jaka celina–deo, deo umire sa celinom (pun romb ◆). Nasleđivanje — „je‑vrsta‑od“ (prazna strelica ▷).

Zapamti
Kompozicija = deo ne postoji bez celine (soba i zid). Agregacija = deo može postojati sam (tim i igrač).

7.Apstraktne klase i interfejsi

Apstraktna klasa ne može se instancirati i može imati apstraktne (bez tela) i konkretne metode. Interfejs je čist ugovor — skup metoda koje klasa mora implementirati. Oba omogućavaju apstrakciju i polimorfizam.

abstract class Oblik { abstract double povrsina(); // apstraktna metoda } class Krug extends Oblik { double r; Krug(double r) { this.r = r; } double povrsina() { return 3.14159 * r * r; } }
Zapamti
Nasleđuješ jednu klasu, ali implementiraš više interfejsa. Interfejs kaže „šta“, klasa kaže „kako“.
