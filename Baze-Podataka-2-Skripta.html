O čemu je predmet. Napredne baze podataka: transakcije (ACID), konkurentnost (anomalije, izolacioni nivoi, zaključavanje, 2PL, mrtva petlja), indeksi (B⁺‑stablo, hash), optimizacija upita (plan izvršenja, selektivnost, trošak) i napredni SQL (podupiti, CTE, prozorske funkcije). Cilj su brze i pouzdane baze.

1.Transakcije i ACID

Transakcija je logička jedinica rada koja se završava sa COMMIT (potvrda) ili ROLLBACK (poništenje). ACID: atomarnost (sve ili ništa), konzistentnost (poštovanje ograničenja), izolacija (kao da se izvršava sama) i durabilnost (trajni upis).

BEGIN;
UPDATE Racun SET saldo = saldo - 100 WHERE id = 'A';
UPDATE Racun SET saldo = saldo + 100 WHERE id = 'B';
COMMIT;   -- ili ROLLBACK

2.Konkurentnost i izolacioni nivoi

Paralelno izvršavanje može dati anomalije: prljavo čitanje (dirty read), neponovljivo čitanje (non‑repeatable) i fantomi (phantom). SQL nivoi izolacije od slabijeg ka jačem: READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE — jači nivo sprečava više anomalija, ali smanjuje paralelizam.

Zapamti
SERIALIZABLE daje rezultat kao neki serijski (redni) raspored transakcija — najjača garancija, ali najskuplja.

3.Zaključavanje, 2PL i mrtva petlja

Zaključavanje kontroliše pristup: deljena brava (S, čitanje) i ekskluzivna (X, pisanje). Dvofazno zaključavanje (2PL) — sve brave se prvo uzimaju, pa tek onda otpuštaju — garantuje serijabilnost. Mrtva petlja nastaje kad dve transakcije čekaju jedna drugu; sistem je detektuje (ciklus u grafu čekanja) i jednu poništava.

4.Indeksi (B⁺‑stablo, hash)

Indeks ubrzava pretragu bez skeniranja cele tabele. B⁺‑stablo podržava tačan pogodak i opsege (BETWEEN, <, >) uz složenost O(log n). Hash indeks je brz za jednakost (=), ali ne za opsege. Indeks ubrzava čitanje, a usporava upis (mora se održavati).

CREATE INDEX idx_student_smer ON Student(smer);
Zapamti
Indeksiraj kolone koje se često javljaju u WHERE i JOIN uslovima i imaju veliku selektivnost (mnogo različitih vrednosti).

5.Optimizacija upita

Optimizator bira plan izvršenja najmanjeg troška (I/O + CPU). Selektivnost uslova procenjuje udeo redova koji prolaze; procenjena kardinalnost = selektivnost × broj redova. Pravila: guraj selekciju i projekciju što ranije (bliže tabelama) i biraj dobar redosled spajanja.

6.Napredni SQL

Podupiti (u WHERE ili FROM) i CTE (WITH … AS) razlažu složene upite. Prozorske funkcije (ROW_NUMBER, RANK, SUM() OVER …) računaju preko „prozora“ redova bez sažimanja u jednu vrstu — koriste OVER (PARTITION BY … ORDER BY …).

SELECT ime, smer,
       RANK() OVER (PARTITION BY smer ORDER BY prosek DESC) AS rang
FROM Student;

7.BCNF i dekompozicija

Šema je u BCNF ako je za svaku netrivijalnu FZ X→Y leva strana X nadključ. Ako nije, dekomponuj: za problematičnu FZ X→Y napravi tabelu (X, Y), a iz originala izbaci Y. Cilj: dekompozicija bez gubitka spajanja i (po mogućstvu) uz očuvanje zavisnosti.
